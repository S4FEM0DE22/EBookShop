# SAFE MODE SHOP — E-book Shop Demo

Production URL: https://safemode-shop.vercel.app/

เว็บร้าน E-book สาธิตตามใบงาน Vibe Coding 2026 ปรับหน้าตาตามภาพต้นแบบ SAFE MODE SHOP: โทนขาวดำ, เมนูทรงแคปซูล, หน้าแรกแบบสไลด์, แค็ตตาล็อก, ตะกร้า, ติดตามคำสั่งซื้อ และโปรไฟล์ลูกค้า ลูกค้าดูสินค้าได้โดยไม่ล็อกอิน แต่ต้องสมัครด้วย Username, Email, Password หรือเข้าสู่ระบบก่อน Checkout และดูคำสั่งซื้อ ระบบใช้ Supabase Auth ในเว็บจริงและบัญชีจำลองที่เก็บรหัสผ่านแบบ scrypt ในเครื่อง ประวัติคำสั่งซื้อผูกกับรหัสบัญชีโดยตรง ไม่ใช่แค่อีเมล จึงเปิดดูได้เฉพาะเจ้าของบัญชี ลืมรหัสผ่านส่งลิงก์ทางอีเมลผ่าน Supabase Auth และการตั้งรหัสผ่านใหม่ทำให้เซสชันเดิมหมดสิทธิ์ แค็ตตาล็อกใช้ PDF ที่ผู้ใช้ให้มา 4 ไฟล์ เลือกซื้อพร้อมกันได้สูงสุด 4 เล่ม แล้ว Checkout เป็นคำสั่งซื้อ `PENDING` หน้าติดตามแสดงรายการเป็นแถวพร้อมปุ่มชำระหรือยกเลิก เปลี่ยนสถานะเป็น `PAID` หรือ `CANCELLED` และแสดงลิงก์ดาวน์โหลดของแต่ละเล่มหลัง PAID ไม่มีการรับเงินจริง

หน้าร้านลูกค้าอยู่ที่ `/` ส่วนหน้าผู้ดูแลอยู่ที่ `/admin/` เมนูและงานของแต่ละฝั่งแยกกัน แต่ใช้ธีมพื้นเข้ม หัวเว็บแคปซูล แผงขาวมุมมน และแถวรายการสีฟ้าเทาให้ใกล้ภาพต้นแบบ หน้าสมัครสมาชิก (`#register`) และเข้าสู่ระบบ (`#login`) แยกกันและมีปุ่มในเมนูเมื่อยังไม่ล็อกอิน เมื่อเข้าสู่ระบบแล้วเมนูแสดงโปรไฟล์แทน และปุ่มไอคอนสีแดงใช้สำหรับออกจากระบบ หน้า `PENDING` มีแผงการชำระจำลองแบบในภาพ โดยไม่มี QR รับเงินจริงและไม่มีช่องเก็บข้อมูลบัตร หลังบ้านมีภาพรวม รีเฟรชข้อมูล ค้นหา/กรองสถานะและเปิดรายละเอียดคำสั่งซื้อ เปลี่ยนสถานะด้วยการชำระเงินจำลอง ยกเลิกรายการที่ยังรอชำระ ลองส่งอีเมลอีกครั้งเมื่อเปิดใช้ Resend ดูรายชื่อลูกค้า และแก้รายละเอียด ราคา หรือเปิด/ซ่อนหนังสือปัจจุบันจากหน้าร้าน ข้อมูลลูกค้าและคำสั่งซื้อทั้งหมดผ่าน API ที่ต้องล็อกอินเท่านั้น

## ทดสอบในเครื่อง

ต้องมี Node.js 20 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```powershell
npm run dev
```

เปิด `http://localhost:3000` แล้วลองครบ flow ได้ทันที ระบบจะเก็บบัญชีทดสอบใน `.data/customers.json` และคำสั่งซื้อใน `.data/orders.json` พร้อมแสดงลิงก์ดาวน์โหลดแทนการส่งอีเมลจริง รหัสผ่านในไฟล์บัญชีเป็น scrypt hash โหมดนี้ใช้ทดสอบบนเครื่องเท่านั้น

หากต้องการทดสอบกับ Supabase ในเครื่อง ให้ใส่ `SUPABASE_URL`, `SUPABASE_SECRET_KEY` และ `DOWNLOAD_SECRET` ใน `.env.local` (ไฟล์นี้ถูกละเว้นจาก Git) แล้วรัน `npm run dev:supabase` แทน `npm run dev` โดยหยุดเซิร์ฟเวอร์เดิมก่อน ไฟล์ `.env.example` เป็นเพียงตัวอย่างและห้ามใส่ secret จริง

การเข้าหลังบ้านต้องตั้ง `ADMIN_PASSWORD` เป็นรหัสสุ่มที่ยาวอย่างน้อย 20 ตัวอักษรใน `.env.local` หรือ Environment Variables ของ Vercel ก่อนเปิด `/admin/` รหัสนี้ใช้เฉพาะเซิร์ฟเวอร์ ไม่บันทึกลง GitHub ระบบออก cookie `HttpOnly`, `SameSite=Strict` อายุ 8 ชั่วโมง และตรวจสิทธิ์ทุกคำขอของหลังบ้าน การกดออกจากระบบล้าง cookie ในเบราว์เซอร์ หากต้องการปิด session ที่ออกไปแล้วทั้งหมด ให้เปลี่ยน `DOWNLOAD_SECRET` แล้ว redeploy ด้วย (จะทำให้ลิงก์ดาวน์โหลดเก่าหมดอายุด้วย)

หน้าติดตามแสดงคำสั่งซื้อของบัญชีที่ล็อกอินตามภาพต้นแบบ พร้อมสถานะ ปุ่ม Mock Payment และปุ่มยกเลิกสำหรับรายการที่ยัง `PENDING` ปุ่มค้นหาเปิด Modal ให้กรอกเลขคำสั่งซื้อ โดยแสดงอีเมลบัญชีแบบอ่านอย่างเดียว หน้าประวัติแสดงทั้งรายการที่ชำระแล้วและรายการที่ยกเลิก บัญชีอื่นเปิดคำสั่งซื้อไม่ได้แม้ทราบเลขคำสั่งซื้อ

```powershell
npm test
```

## ตั้งค่า Supabase และอีเมล

1. สร้าง Supabase project แล้วรัน [schema.sql](supabase/schema.sql) และ [customer_accounts.sql](supabase/customer_accounts.sql) ตามลำดับใน SQL Editor จะได้ตาราง `books`, `orders`, `customer_profiles` ที่เปิด RLS, owner ID สำหรับคำสั่งซื้อ และ private Storage bucket ชื่อ `ebooks`
   เปิด Authentication > Providers > Email สำหรับบัญชีลูกค้า ตั้ง Authentication > URL Configuration > Site URL และ Redirect URLs เป็น `https://safemode-shop.vercel.app/` เพื่อให้ลิงก์ยืนยันอีเมลและลืมรหัสผ่านกลับมาที่ร้าน โปรเจกต์ปัจจุบันตั้งสองค่านี้แล้ว อีเมลยืนยันและรีเซ็ตส่งด้วย Supabase Auth แยกจาก Resend ที่ใช้ส่ง E-book
2. อัปโหลดเฉพาะ PDF ทั้ง 4 ไฟล์ในตารางข้างบนจาก `private-books/` ไปยัง bucket `ebooks` โดยคงชื่อไฟล์เดิม และตรวจว่า bucket **ไม่เป็น public**
3. สร้าง Resend API key และยืนยันโดเมนผู้ส่ง แล้วใช้ที่อยู่นั้นใน `EMAIL_FROM` ถ้าใช้โดเมนทดสอบของ Resend อาจส่งได้เฉพาะอีเมลบัญชีผู้สร้าง
   หากต้องการให้ลูกค้าทั่วไปได้รับอีเมลยืนยันบัญชีและลืมรหัสผ่าน ต้องตั้ง **Authentication > Emails > SMTP Settings** ใน Supabase ด้วย ปัจจุบันยังไม่ได้เปิด custom SMTP; ผู้ส่งอีเมลเริ่มต้นของ Supabase ส่งได้เฉพาะสมาชิกทีมโปรเจกต์ การมี `RESEND_API_KEY` ใน Vercel อย่างเดียวไม่เปิดอีเมล Auth
4. ตั้งค่า Environment Variables ใน Vercel ตาม [.env.example](.env.example): ต้องมี `SUPABASE_URL`, `SUPABASE_SECRET_KEY` และ `DOWNLOAD_SECRET`; เพิ่ม `ADMIN_PASSWORD` เพื่อเปิดหลังบ้าน และเพิ่ม `RESEND_API_KEY` กับ `EMAIL_FROM` เมื่อพร้อมส่งอีเมลจริง ส่วน `PUBLIC_SITE_URL` ไม่จำเป็นหากใช้ URL ของคำขอ ห้ามนำ secret ใส่หน้าเว็บหรือ GitHub
5. เชื่อม repository กับ Vercel แล้ว deploy โดยใช้ root directory ของโปรเจกต์นี้ โปรเจกต์กำหนด `framework: null` และ output directory เป็น `public` ใน `vercel.json` แล้ว ไม่ต้องมี build command จากนั้นเปิด Production URL เพื่อทดสอบครบ flow

`SUPABASE_SECRET_KEY` เป็น secret key รูปแบบใหม่ (`sb_secret_...`) หรือ service_role key แบบเดิม ใช้เฉพาะ server function เท่านั้น `DOWNLOAD_SECRET` ต้องเป็นสตริงสุ่มอย่างน้อย 32 ตัวอักษร เมื่อเปลี่ยนค่าตัวแปรให้ redeploy

## วิธีทำงานของลิงก์ดาวน์โหลด

หลัง `PAID` ระบบส่งอีเมลด้วย Resend เมื่อกำหนด `RESEND_API_KEY` และ `EMAIL_FROM` พร้อมลิงก์แยกแต่ละเล่ม อายุประมาณ 24 ชั่วโมง หากยังไม่ได้ตั้งค่าหรือส่งไม่สำเร็จ คำสั่งซื้อยังเป็น `PAID` และมีลิงก์ดาวน์โหลดบนหน้าเว็บ พร้อมปุ่มลองส่งอีเมลอีกครั้ง เมื่อเปิดลิงก์ API จะตรวจสถานะและตรวจว่าเล่มนั้นอยู่ในคำสั่งซื้อ แล้วออก Supabase Storage signed URL อายุ 5 นาที ไฟล์อยู่ใน private bucket วิธีนี้จำกัดการเข้าถึง แต่ไม่ใช่ DRM และผู้รับยังสามารถส่งต่อไฟล์ได้
